# FlappyBird 测试计划

- 版本：v1.0
- 日期：2026-11-23
- 被测版本：FlappyBird 1.0（110 个单测通过，覆盖率 67%）
- 依据：[需求文档](../specs/2026-11-23-flappybird-design.md) · [实施计划](../plans/2026-11-23-flappybird/flappybird.md)
- 测试类型：手工/脚本混合（可复现脚本见 [缺陷报告](defect-report.md)）

## 1. 测试目标

1. 验证核心玩法闭环（起飞→穿管→计分→碰撞→坠落→结算→重开）在**每个状态**都正确。
2. 验证 Spec §6 的 41 条编号需求（FR-WIN/INPUT/STATE/PHYS/DIFF/THEME/AUDIO/SCORE/STORE/SCREEN/ASSET）可被观测证据证实。
3. 找出当前实现中**与需求不符**或**用户可感知**的缺陷，给出可复现步骤与影响评估。
4. 建立可回归的测试基线：本次新增的探索性验证点，凡可自动化的都应固化为 pytest 用例。

## 2. 测试范围（已与需求方确认）

| 编号 | 边界（seam） | 说明 | 本轮是否覆盖 |
|---|---|---|---|
| S1 | 纯逻辑层 | `physics` / `difficulty` / `score_store` 的公开函数 | ✅ 覆盖 |
| S2 | 状态机层 | 5 个 State 的 `handle_key` / `update` / `draw` | ✅ 覆盖（核心） |
| S3 | 集成层 | `Game.handle_events` / `set_state` / `draw_frame` | ✅ 覆盖 |
| S4 | 渲染层 | 离屏 Surface 像素采样 | ✅ 覆盖 |
| S5 | 进程层 | `main.py` 退出码、缺失素材、损坏存档 | ⬜ 本轮不覆盖（子进程/环境隔离测试，风险低，现状已由既有单测部分覆盖） |
| S6 | 真实窗口/人手试玩 | 手感、音效、窗口缩放 | ⬜ 不覆盖（无法自动化，仅列手工用例） |

**明确不在范围内**：性能压测（另见 §7 已做的一次性观测）、跨平台（项目目标为 Windows）、网络/多用户（无此功能）。

## 3. 测试策略

### 3.1 分层策略

```text
S1 纯函数  ──  单元测试，100% 分支覆盖，穷举边界值
S2 状态机  ──  状态 × 输入 的矩阵测试（5 状态 × 6 键 = 30 组合）
S3 集成    ──  单帧驱动 + 事件注入，验证跨组件协作
S4 渲染    ──  离屏渲染 + 像素/行面积采样，验证视觉契约
S6 手工    ──  按用例表逐项执行，记录观感
```

### 3.2 测试数据设计方法

| 方法 | 应用点 |
|---|---|
| 等价类划分 | 分数区间（0 / 1-4 / 5 / 6-9 / 10 / 30+）；缝隙值（110/105/…/80） |
| 边界值 | 计分边界 `pipe.x+PIPE_W == bird_left`；死亡边界 `y+h == LAND_Y`；缝隙上限 `MIN_GAP` |
| 状态迁移覆盖 | 5 态 × 合法/非法迁移，重点覆盖**非法输入被忽略** |
| 错误猜测 | 损坏存档、只读目录、无音频设备、缺失素材、连续极端操作 |
| 不变量 | 「同一随机种子 + 同一输入 → 同一结果」「分数单调不减」「难度单调」 |

### 3.3 严重程度定义

| 级别 | 定义 | 处理时限建议 |
|---|---|---|
| **P0 致命** | 游戏无法启动、无法游玩、崩溃、存档损坏丢失 | 立即修复 |
| **P1 严重** | 核心玩法规则错误、需求明确约定但未实现、用户明显可感知 | 本版本修复 |
| **P2 一般** | 体验瑕疵、边缘场景异常、视觉不精致 | 可延后 |
| **P3 轻微** | 代码异味、未使用配置、文档不一致 | 随版本清理 |

## 6. 进入与退出准则

**进入准则**：代码可 import、110 个既有单测全绿、素材体检 PASS。

**退出准则**：
- P0/P1 缺陷全部记录且**有明确复现步骤**；
- 76 条用例中 P0/P1 用例 100% 执行，P2/P3 用例执行率 ≥ 80%；
- 缺陷报告中的每个问题都能被第三方独立复现。

## 7. 已有的自动化基线（本轮之前）

| 指标 | 数值 |
|---|---|
| 单测数量 | 110 |
| 通过率 | 100% |
| 行覆盖率 | 67% |
| 覆盖率低谷 | `game.py` 0%、`display.py` 41%、`pipe.py` 60%、`states/ready.py` 58%、`states/gameover.py` 60% |

**覆盖率低不等于有缺陷，但意味着这些路径缺少回归保护**——本轮的探索性测试恰好验证了这一点：`game.py` 与 `states/*.py` 的未覆盖分支中藏着 P1 缺陷（详见缺陷报告）。

## 8. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 无人工试玩 | 手感/音效类问题无法评估 | 用例表标注"手工"，由需求方执行 |
| 单机无并发 | 无并发测试 | 不适用 |
| 渲染像素断言依赖 1× 缩放 | 换机器（2× 屏幕）可能失效 | 像素断言只用于逻辑画布，不依赖窗口尺寸 |
| dummy 音频驱动 | 无法验证真实发声 | 只验证调用路径与降级，音质需人工听 |
