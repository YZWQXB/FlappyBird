[08] 手感调优
================================================================================
提示词原文：

重力下降太快了，连续高低障碍很难飞跃调整下降速度，空格按下后在空中有一段短暂
悬空不要立马就掉落

--------------------------------------------------------------------------------
响应摘要：

【先量化"下降太快"】没有凭感觉调参：
  | 指标            | 调整前   | 判定 |
  | 单跳总滞空       | 0.500 s | 太短 |
  | 顶点悬停         | 0.000 s | 完全无悬停，正是"立马就掉落" |
  | 离开顶点落 60px  | 0.133 s | 0.13 秒就掉一大截 |
  | 终端下落速度     | 640 px/s| 长距离下坠无法控制 |

【方案：非对称重力 + 顶点滞空】实现于 physics.gravity_for()
  base = GRAVITY if vy < 0 else GRAVITY * 0.65        # 下降更轻
  if |vy| >= 120: return base
  return base * (0.35 + 0.65 * |vy|/120)               # 顶点附近重力更小

  三个设计决定：
  1. 没做成"跳跃后短暂无重力"——那样会变成"按一下飘 0.3 秒"的发木手感，
     且输入响应不连续。这里用纯粹的速度-加速度关系：顶点附近重力小所以
     自然飘，一旦开始下落重力迅速恢复所以保留"重力感"，补跳响应始终即时。
  2. 同时降低终端速度（640→480）：只改顶点滞空解决不了"从高处直坠"。
  3. 阈值处连续：曲线在 |vy|=120 处恰好接回基准值，不会产生可感知卡顿。

【效果】
  | 指标      | 调整前   | 调整后    | 变化 |
  | 单跳升高   | 45.0 px | 46.2 px  | 持平 |
  | 总滞空     | 0.500 s | 0.667 s  | +33% |
  | 顶点悬停   | 0.000 s | 0.317 s  | 从无到有 |
  | 落 60px   | 0.133 s | 0.167 s  | +26% |
  | 终端速度   | 640 px/s| 480 px/s | -25% |

新增 tests/test_feel.py（14 条）锁定手感下限，以后任何人调参把浮动感改回去
都会立刻失败。用轨迹对比图直观展示新旧曲线的差异。

================================================================================
                                经验教训汇总
================================================================================
1. 矩形相交 ≠ 视觉遮挡。判断遮挡必须按绘制顺序和实际像素验证。（D-05 撤回）
2. 子智能体的结论必须独立复验。两条"缺陷"经复验是误报。（第 09 轮）
3. 修一个缺陷可能引入新的视觉问题，"缺陷消失"的断言不足以验收，必须重新看图。
4. 单元测试覆盖不到真实重启链路，端到端测试抓到了守卫逻辑 bug。（第 07 轮）
5. "110 个测试全绿"不等于质量好——它们覆盖的是纯函数而非用户可见行为。
   本轮每个缺陷都恰好落在覆盖率低谷区。
6. 简单 bot 不能作为手感判据（单次跳跃期间无法反向修正），
   应用解析判定 + 物理可达性分析替代。（附录 A.4）
7. 环境事实要实测，不要假设：桌面 1707×1019 放不下 576×1024、
   SysFont 在本机必抛 TypeError，这些都改变了设计。
